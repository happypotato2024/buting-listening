# 源码与构建

本仓库是 2.0 正式版的源码整理，不是 Gradle / Android Studio 一键工程。Android Java 源码由 Python 脚本调用 Android SDK 的 aapt2、javac、D8、zipalign 和 apksigner 构建；原生识别及翻译库由 CMake / NDK 构建。当前脚本面向 **Windows x64**。

## 目录与依赖

- Python 3.11+；生成图标 / 像素校验另需 Pillow。Node.js 20+；JDK 17+。
- Android Platform 35 的 `android.jar`，Build Tools 35.0.0。
- Android NDK r27d；CMake 3.31.6（含 Ninja）。
- whisper.cpp v1.8.2、llama.cpp v0.6.0 的源码及各自 LICENSE。
- 资料仓库固定提交 `738ab7b66999933761a1077870d56a5a46ad5433`。
- 自己的 APK 签名密钥。正式发行密钥不公开。

`listening-android/content` 提供界面，`src` 提供正式版入口与桥接；`listening-lab/src` 是共用引擎。正式版构建会排除测试版 MainActivity，调整资源与版本、注入固定两线程和正式版播放恢复逻辑，保持 JNI 类名不变。`listening-app/dist/app.js` 与 `core.js` 是当前构建所用的基础脚本源码，必须保留。

## 1. 准备资料

在项目根目录执行：

```powershell
git clone https://github.com/happypotato2024/buting-listening-resources.git github
git -C github checkout 738ab7b66999933761a1077870d56a5a46ad5433
```

这会下载资料仓库的录音等大文件。正式版打包时只读取目录和时间标记，不将录音加入 APK。不要把整个 `github/` 再提交到软件仓库。

## 2. 准备原生工具与引擎

默认缓存目录为 `$env:TEMP/buting-lab-toolchain`，以下相对目录需要存在：

```text
buting-lab-toolchain/
  android-ndk-r27d/       # NDK 解压目录
  cmake/bin/             # cmake.exe、ninja.exe
  whisper.cpp-1.8.2/      # 完整源码，含 LICENSE
  llama.cpp-0.6.0/        # 完整源码，含 LICENSE
```

版本下载可从 [Android NDK](https://developer.android.com/ndk/downloads/older_releases)、[whisper.cpp v1.8.2](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.8.2)、[llama.cpp v0.6.0](https://github.com/ggml-org/llama.cpp/releases/tag/v0.6.0) 获取。CMake 可由 Android SDK Manager 安装，再将其目录放入上述位置。请使用可信的官方发行并核验下载。

```powershell
python listening-lab/tools/native-build.py arm64-v8a
python listening-lab/tools/native-build.py x86_64
```

会生成 `libs/<ABI>/libbuting_whisper.so` 和 `libbuting_translate.so`。构建 APK 不需要下载模型权重。

## 3. 配置 SDK、Java 与签名

设置本机实际路径，以下只是示例：

```powershell
$env:JAVA_HOME = 'C:/Dev/jdk-17'
$env:BUTING_ANDROID_JAR = 'C:/Android/Sdk/platforms/android-35/android.jar'
$env:BUTING_BUILD_TOOLS = 'C:/Android/Sdk/build-tools/35.0.0'
$env:BUTING_KEYSTORE = 'C:/PrivateKeys/my-release.p12'
$env:BUTING_KEY_ALIAS = 'my-release'
```

用自己管理的密钥签名。构建前通过当前进程的 `BUTING_SIGNING_PASSWORD` 环境变量提供密码；不要把密码写入仓库、命令日志或公共配置。脚本使用同一密码打开 keystore 与私钥。维护者本机仍可使用被忽略的 `.signing/config.json` 和 `.signing/tingjian-release.p12`。

可选 `BUTING_TOOLCHAIN_CACHE`、`BUTING_NDK_HOME` 调整正式 APK 构建路径；原生编译脚本默认仍读取上述 TEMP 缓存目录。

**自己的签名无法覆盖安装本仓库官方签名的 APK。** 在测试设备 / 独立模拟器上验证自己的构建，不要卸载有重要记录的正式版来绕过签名冲突。

## 4. 构建

```powershell
python listening-android/tools/build-formal.py
```

输出在缓存目录 `formal-build/signed.apk`，版本信息写入 `listening-android/build/latest-apk.json`。设置 `FORMAL_DELIVER=1` 会另复制到项目根目录。当前公开 Release 是用户已验收、哈希固定的原安装包，不因本次文档与构建路径参数整理而重新签包。

## 5. 检查

```powershell
node listening-android/tools/test-home-core.mjs
node listening-android/tools/test-study-core.mjs
```

`tools/FormalChecks.java` 是运行在目标 Android 应用进程中的仪器测试，覆盖首页、播放、后台、布局、失败重试与升级数据；测试会写入模拟器学习记录，应只在测试设备运行。其构建辅助脚本和 `verify-formal.py` 保留维护者环境路径 / 旧正式版签名比较前置条件，使用前需要调整。历史测试报告不是新设备通过测试的保证。

正式构建的 UI 可先用 `prepare-formal.mjs` 输出到临时目录检查；它需要第 1 步的资料。无需重复处理或翻译资料。
